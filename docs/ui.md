# 界面指南

> 定位：插件在 DSH 界面中的全部出入口与交互。

## 「远程工作区」面板

侧边栏面板，注册在 `sidebar.panellist` 插槽，入口图标为服务器图标（`ServerIcon`），标题「远程工作区」。

主机卡片逐条展示存储与 `~/.ssh/config` 回退的全部主机，字段为别名、`user@host:port`、认证方式、来源（store / ssh-config），以及「密钥未就绪」提示（key 认证且 `keyPath` 在本机不存在时）。每张卡片提供：

- **测试连接**：调用 `POST /api/dsh-ssh-workspace/test` 实连一次，**然后释放这条连接**——「测试」回答的是「这台主机是否可达」，不是「替我连上」。结果以页面顶部 toast 呈现（成功附往返毫秒数），成功后数秒（约 3.5 s）自动消失，点击可提前关闭；失败消息同样处理。连接指示点因此不会被一次探测点亮：刷新读的是实际剩下的连接，而不是假定测试留下了一条。测试吃到**主机密钥不匹配**拒绝时，卡片行内直接展开恢复区（双指纹 +「忘记此主机密钥并重试」，见下文「主机密钥不匹配的就地恢复」），不再是一句指回面板的死路文案。
- **断开**：仅在该主机存在池化 SSH 连接时显示（连接状态指示绿点内联在主机名之后）。点击调用 `POST /api/dsh-ssh-workspace/hosts/disconnect` 关闭该主机的池化连接，**并连带拆除该主机上的全部端口转发**（响应里的 `closedForwards` 报告拆了几条，toast 据此改写为「已断开连接，同时关闭 N 条端口转发」）。拆除的结果与在端口转发行上点「断开」**完全一致**：映射保留、意图置为断开、不记任何失败原因——主动断开不是故障，面板不该对它亮红字或提示「下次启动会自动开启」。连接上有操作进行中（进行中数量大于 0）时按钮禁用并给出提示。断开无需确认——下一次操作会按需重连。
- **忘记主机密钥**：调用 `POST /api/dsh-ssh-workspace/hosts/forget-key` 清掉该别名的 TOFU 主机密钥记录（需就地确认），用于主机确实重装系统或更换密钥之后——见 [hosts.md](./hosts.md) 的「主机密钥校验」。
- **浏览目录**：打开该主机的目录浏览器（见下节）。它与「新建远程工作区」里的目录选择是**两个不同的组件**（这里是 `DirectoryBrowser`，那里是 `RemoteWorkspaceDialog`）：后者只列目录、只为选路径，前者还带上传与逐行下载。共同点是挂载入口在两边都有——毕竟从主机卡片点进来，多半就是为了挂载。
- **编辑 / 删除**：编辑打开主机表单；删除为就地确认，删除只影响存储条目，不会自动卸载已挂载的工作区。

表单要点：密码与密钥口令**从不回传浏览器**，编辑时留空表示保留原值（见 [hosts.md](./hosts.md) 的「认证与凭据」）；切换认证方式时必须重新填写新凭据。

**测试连接（新建与编辑都有）**：表单底部一排的「测试连接」按钮，用**表单当前值**实连一次——不要求先保存，新建到一半的主机也能测。探测走 `POST /api/dsh-ssh-workspace/probe`（草稿通道，见下文），服务端为它开一条**一次性连接**：连接池与主机存储都不被读写（草稿若与某台已保存主机同名，探测也不会复用或挤掉那条池化连接），表单里现填的密码 / 口令只活在这一次连接的内存里，随连接关闭消散。编辑已存主机时，密码 / 口令留空表示「沿用已存的」——服务端会从存储回填给这次草稿连接（当然也不会回传浏览器）。成功 toast 附往返毫秒数，表单内同时留一行持久结果；失败按连接错误分类给出可操作的提示（认证失败 / 超时 / 解析不了主机名等）。必填字段（别名、主机地址、用户名、对应认证字段）没填好时按钮禁用并以悬停提示说明缺什么。

「操作系统」一行是下拉框（Linux / macOS / Windows / 自动）：它钉死主机的
操作系统与命令方言——`mac` / `linux` → POSIX shell、`win` → 优先用主机自己的
POSIX bash（钉了 Bash 路径、部署过载荷或探测得到），一个都没有才回退 cmd.exe，
选「自动」保存则删除条目里的 `os` 字段、回到按连接探测。**新建主机默认选
Linux**；编辑一台从没存过 `os` 的旧主机时初始显示「自动」而不是 Linux——把
探测出 Windows 的主机钉成 Linux 会让它的远端命令全部失灵，这个默认值只在用户
明确选过之后才落盘。主机卡片的 meta 行同样显示当前生效的操作系统（没存过的
显示「自动」）。

「Bash 路径」一行只在选了 **Windows** 时出现（可选输入框）：钉死该 win 主机的
POSIX bash 可执行文件绝对路径（如 `C:\Program Files\Git\bin\bash.exe`），是
引擎 bash 解析的第一优先级；留空则自动探测常见安装位置与 PATH，探测不到可用
`ssh_workspace_bash` 工具部署钉版载荷，都没有才回退 cmd.exe。把 OS 切离
Windows 再保存会一并清掉已存的 Bash 路径，避免把 bash 钉到 POSIX 主机上。

「自动部署 Niubash」复选框同样只在选了 **Windows** 时出现（紧随 Bash 路径
之后，存储字段 `niubashAutoDeploy`）。它有**三态**：新建主机**默认勾选**（保存
即在后台自动部署）；编辑已有主机回显存储值，条目里没有该字段的旧主机默认
**不勾**——一次普通保存绝不会给存量主机凭空触发部署；已初始化（有
`bashProvisioned` 记录）的主机**置灰**并把小字换成「Niubash 已初始化：部署已
存在，自动部署不会再触发」。勾选框下方的小字注明默认部署目标
`<用户目录>\.dsh\runtimes\plugins\dsh-ssh-workspace\niubash\` 与「放置路径可在
『初始化 Niubash』弹窗更改」——编辑器里**不放路径输入**，换放置路径只有弹窗
一个入口。触发时机、失败策略与目标解析见 [hosts.md](./hosts.md) 的「自动部署」。

「默认目录」一行是输入框加**选择…**按钮：按钮打开一个叠在表单之上的轻量目录选择器（`DefaultPathPicker`，第二层遮罩对话框），只列目录、可点面包屑导航；当前目录不可写时同样亮红字——拿不可写目录当默认值，之后每次新建工作区都会从那条警告开始。点「确定」把当前路径写回输入框，仍走保存时的规范化。按钮在**表单填好可连接的连接信息**时即可用（别名、主机地址、用户名、认证字段齐了就行）：选择器走草稿通道 `POST /api/dsh-ssh-workspace/probe`（`action: 'ls'`）浏览，**浏览即实连**——新建未保存的主机照样能选目录，不再要求「先保存主机，再编辑选择」；表单没填好时按钮禁用并以悬停提示说明还缺什么。`~/.ssh/config` 回退主机本就没有编辑入口，服务端也拒绝写入。

「在工作区名称下显示主机标签」是默认关闭的开关（存储字段 `aliasTag`）：开启后，侧栏中凡是挂载自该主机的远端工作区，其**工作区名称下方**都会显示一枚小标签，内容是该主机的别名——多台主机的工作区挤在同一个侧栏里时，靠这枚标签就能分清各行属于哪台主机。表现见下文「远程工作区标记」的「主机别名标签」一节。

## 添加工作区双入口

插件占用两个 directoryFlow 插槽：侧边栏的 `sidebar.workspaces.directoryFlow` 与会话页的 `conversation.hero.workspace.directoryFlow`，以负优先级（`-100`）遮蔽部署自带的本地选择器——插槽核心渲染优先级**最低**的占用者，负优先级因此胜出，且不卸载内建实现。

触发后弹出锚定菜单（宽约 300px），包含两行：

- **本地**（FolderIcon）：转交 DSH 原生目录选择器——桌面端走 preload 桥 `__DSH_DIRECTORY_PICKER__`，否则走 `uiWorkspace.pickDirectory()`。
- **远程**（远程标记图标）：打开「新建远程工作区」对话框。

锚定机制：触发按钮不传给插槽占用者，因此插件在捕获阶段监听 `mousedown` 记住最近一次按钮位置（3 秒内有效，避免键盘快捷键打开时菜单"瞬移"），弹出层定位在按钮右侧 8px 处，并钳制在视口内；窗口 resize 时重新定位。点击菜单外部或按 Esc 关闭。

## 浏览目录对话框

点主机卡片的「浏览目录」打开 `DirectoryBrowser`（`lib/client.js`）。它与「新建远程工作区」里的目录选择**不是同一个组件**（后者是 `RemoteWorkspaceDialog`，只列目录、只为选路径），因此两者能力不同：

- 顶部：返回上级、可点击的路径分段（面包屑，点早期分段直达其目录；挂载 / 上传 / 下载进行中时分段不可点）、**上传文件**（`POST /upload`，原始字节流）；
- 列表：目录在前、按名排序；文件行显示大小并带 **下载到本机**（`GET /download`，流式返回原始字节），目录行没有下载按钮——整个目录不能作为一个文件拉下来；
- 底部：「挂载此目录」——按当前路径创建远程工作区，成功后附**能力提示**（`capabilityNotes`：`rg` / `git` / `inotifywait` 的缺失项，只报探测出的确定缺失）。

首帧路径为 `null`，首次 `GET /ls`（不带 `path`）返回 SSH 登录目录后回填，所以「挂载此目录」永远指向一个真实绝对路径。加载中 / 空目录 / 无法加载是三种独立状态。

上传与下载各有自己的忙碌标记：一次只跑一个传输，第二个点击会被忽略，且**上传失败不会清掉下载的错误**，反之亦然。失败信息常驻对话框内而不是走 toast——对话框开着时用户不会去看页面角落。

## 对话框的遮罩关闭（`backdropDismiss`）

`HostEditor`、`DirectoryBrowser`、`RemoteWorkspaceDialog`、`LocalDirectoryBrowser` 与
`AgentPromptsEditor`（agent 提示词编辑器，全局 / 工作区两级入口共用，见
[agent-prompts.md](./agent-prompts.md)）五处共用 `backdropDismiss(close)`：判据是**按下与松开都落在遮罩上**，而不是「click 落在遮罩上」。

差别不是学究式的。`click` 的事件目标取**按下点与松开点的最近公共祖先**——在输入框里拖选一段文字、把鼠标拖到对话框外再松开，按下在对话框内、松开在遮罩上，浏览器仍会把 click 派发到遮罩，于是 `onClick: onClose` 会在用户选字的半途把整个流程关掉。按下点才是可靠信号。

四条附带规则，每条都对应一种会回退的行为：

- **只认主键**（`event.button === 0` 才置位）。`click` 从不为副键派发，若不加这道门，「右键按在遮罩上松开」会凭空多出一个关闭动作，而右键本该只弹上下文菜单。**松开侧刻意不设这道门**：touch / pen 的 `pointerup` 在部分引擎里报 `button: -1`，门住它会让触屏点空白再也关不掉。
- **状态写在元素上，且每次 `pointerdown` 无条件覆写**。按下后把鼠标拖出窗口再松手，多数平台根本不派发 `pointerup`；若靠「松手时清理」，残留的「已按下」会漏到下一次手势里，反而在用户从对话框内按下时误关。因为遮罩是祖先节点，来自对话框内部的按下会冒泡到它并把标志覆写为 false。
- **忙碌时关闭被拒**：编辑对话框存盘中、目录浏览器传输中、创建工作区接纳中、提示词编辑器加载中或存盘中都不可用遮罩关闭（各自的门禁写在组件的 `dismissBackdrop` 里），否则会把仍在进行的请求连同它唯一的反馈一起丢掉。
- **对话框本身没有 Escape 关闭**。三个组件都没绑键盘关闭，遮罩收紧后唯一的出口是各自可见的「取消 / 关闭」按钮与标题栏的 ×。这是现状而非遗漏：加 Escape 必须处理「下拉框或文件选择器正吞这个键」的先后，需要真机浏览器验证，不在 0.2.5 范围内。

## 新建远程工作区对话框

一次完成"选主机 → 选目录 → 命名 → 挂载"：

1. 拉取主机列表，默认选中第一台；主机列表为空或出错时给出对应空态。
2. 目录浏览：`GET /api/dsh-ssh-workspace/ls?alias=…&path=…` 逐级浏览远端目录，只列目录、按名称排序；提供「返回上级」、可点击的路径分段（面包屑，盘符路径 `/C:/…` 与 POSIX 路径都支持）、加载中 / 空目录 / 无法加载三种状态。主机配置了 `defaultPath`（默认目录）时，初始目录取主机默认值而非 SSH 登录目录，切换主机同样按新主机的默认目录重新定位。「无法加载」按失败种类分两种呈现：普通加载失败（网络 / 路径不存在等）保留错误信息并附一个「重试」按钮；**主机密钥不匹配**则展开恢复区（见下文「主机密钥不匹配的就地恢复」）。
3. **可写探测**：`/ls` 同时回报 `writable`，探测方式是在同一 SFTP 通道上向目标目录**实际创建一个临时文件**（`.dsh-wprobe-<随机hex>` 空文件，优先 `wx` 独占创建、服务器不支持时降级默认 flag 重试一次，完成后删除）——建得成即可写，建不成即不可写，探测失败不会拖垮 `/ls`。不依赖远端 shell 方言（此前用 shell `test -w`，在默认 shell 为 cmd.exe 的 Windows 主机上必然失败，所有目录都被误报不可写）。目录不可写时显示红色警告（"当前 SSH 账号对这个目录没有写入权限……"）并禁止创建——写入能力是 Agent 工作的前提。
4. 创建：`POST /api/dsh-ssh-workspace/mount`，携带 `{alias, remotePath, title, register: true}`。**先注册、后接纳**：挂载路由在宿主接纳该路径之前就按所填名称登记工作区，宿主随后解析到既有记录，避免以派生标题重复建条目。成功后刷新标记数据源，把路径交还吸附链路；对话框在接纳期间保持禁用，背景点击可取消（创建中除外）。
5. **设为本主机默认目录**（复选框，默认不勾，挂在目录字段下方）：勾选后，挂载成功会把当前浏览的目录经 `POST /api/dsh-ssh-workspace/hosts/default-path` 记为主机的 `defaultPath`，下次在这台主机上新建工作区就从这里开始浏览。**挂载成功是主交付，默认目录记录是附属动作**：这一步失败（主机被并发删除、网络抖动等）只在控制台留一条警告，不弹错、不影响工作区交付。主机来自 `~/.ssh/config` 回退（只读）时复选框禁用并以悬停提示说明原因——服务端对这类主机同样直接 400。

## 主机密钥不匹配的就地恢复

凡是可能吃到主机密钥拒绝的地方——「新建远程工作区」对话框、目录浏览器、默认目录选择器、主机卡片的「测试连接」、主机编辑器自己的「测试连接」——错误态都不再是一句「去面板忘记主机密钥」的死路文案，而是就地展开恢复区：

- **双指纹结构化呈现**：服务端把拒绝以 `error.code = 'hostKeyMismatch'` + `mismatch` 字段（`{alias, recorded: {keyType, fingerprint, recordedAt?}, presented: {keyType, fingerprint}}`）随错误响应带给浏览器，客户端渲染「已记录 / 本次出示」两行指纹（含密钥类型与记录时间），**从不解析报错文案**——指纹一旦只活在英文 prose 里，措辞一动恢复就瞎。
- **「忘记此主机密钥并重试」**：第一步只是展示；点击后进入确认步骤，再次并列显示两个指纹并给出**中间人警示**（「若你没有预期到这次密钥变更，不要继续……继续将以新密钥重新记录（TOFU）」），确认后才 `POST /api/dsh-ssh-workspace/hosts/forget-key`，然后**自动重试刚才失败的那次操作**（列表 / 测试）——重连即以新密钥重新 TOFU，插件从不静默信任变更后的密钥。
- **普通失败不受影响**：非密钥类的加载失败保持「错误信息 + 重试」的简单呈现，不会误入确认流程。

面板主机卡片行内同样接这条链路：卡片上的「测试连接」吃到拒绝时，恢复区就在该卡片行内展开，确认后先忘记密钥再自动重测。

## 草稿探测通道（`POST /api/dsh-ssh-workspace/probe`）

主机编辑器的「测试连接」与新建模式下的默认目录选择共用一条**草稿探测**路由：请求体携带表单当前值（`{action: 'test'|'ls', draft, path?}`），服务端按草稿开一条**一次性 SSH 连接**，测完 / 列完即关闭。三条刻意为之的语义（实现见 `lib/engine.js` 的 `withDraftSftp`）：

1. **不碰连接池**：草稿可能与某台已保存主机同名但带着不同的凭据，走池子会复用或挤掉用户正在用的连接——草稿永远自带新连接；
2. **验密钥但不钉密钥**：草稿连接照样对照已有的 TOFU 记录（已知变更过的密钥在浏览流程里同样会被拦下、走就地恢复），但**不写入**新记录——为改了名或从没保存的主机留指纹，只会在共享的 `dsh-ssh.json` 里攒孤儿记录；保存后的首次真实连接自然会 TOFU；
3. **草稿密文不落盘**：表单里现填的密码 / 口令只活在这一次连接的内存里；编辑已存主机时留空的密码 / 口令由服务端从存储**回填给这条草稿连接**（编辑表单不回显密文，「编辑 → 测试」不重输密码才可能通过）。

`action: 'ls'` 的应答与 `GET /ls` 同形（`path` 回显、`entries`、`writable`），客户端因此用同一套渲染代码服务「已保存」与「草稿」两个世界。

## 浮动远端工作区（工作区 ⋯ 菜单）

一个项目可以配多条 SSH 远端，但不必让它们各占一行：在工作区行的 ⋯ 菜单里选择
「SSH 远程工作区 ▸」，即可配置、选中并让它在**该项目的位置上浮动显示**。

- 菜单块**追加**在官方菜单末尾（分隔线 + 一级项 + 自绘二级子菜单），
  ao-local / better-sidebar 已注入的项保持原位；注入后做一次视口夹取。
- 二级菜单每条：自动名 + `user@host` + 状态（浮动中 / 已挂载 / 未挂载 / 主机缺失），
  点击 = 选中（必要时挂载）并进入浮动；另有「＋ 添加此项目的 SSH 远端…」、
  「管理…」与（浮动中时的）「退出浮动显示」。
- 二级菜单**打开零闪动**：条目列表缓存在 localStorage（`dsh-ssh-workspace:floating:v1`，
  只做显示提示），启动时读回，首次展开直接画上次数据；重绘先比签名，数据没变
  就完全不动 DOM；一次打开只发一次 `/floating/list`（展示路径共享 in-flight 请求，
  后台静默刷新；增删改走 `force` 拿写入后的新状态）。
- 选中后一个**不透明卡片**从左侧滑入，盖住侧栏工作区列表：顶部是插件画的头部条
  （`浮动` 徽标 + 配置名 + `alias@host` + 关闭 ×），卡内是该工作区的**原生行**
  （工作区行 + 会话行）——新建会话、⋯ 菜单、重命名、删除、归档、收藏、拖拽以及
  其它插件注入的菜单项全部照旧。
- 非浮动时，该远端的工作区行与其会话行从正常工作区列表隐藏；工作区选择器菜单行
  与会话页 hero 工作区按钮按标题隐藏（仅当标题命中本插件的远端身份集合）。
- 添加对话框没有名称输入框，名称自动生成（`目录名 · 主机别名`，同父下重名追加
  ` #2`）；添加只是配置，选中菜单项时才挂载。管理面板支持改名、排序、测试连接、
  删除（可勾选同时注销该 DSH 工作区）与清理失效条目。
- 刷新页面即退出浮动（浮动状态只在页面内存），被隐藏的行仍按配置隐藏。

完整语义（存储格式、五条路由、状态判定、降级点）见
[floating-workspaces.md](./floating-workspaces.md)；对官方菜单的注入契约见
[被扩展说明.md](./被扩展说明.md)。

## 远程工作区标记

远程工作区不以文件夹图标示人，而是显示 SSH 标记。DSH 的行图标没有插件插槽，实现为 **DOM 装饰**（`lib/client.js` 的 "Remote-workspace marks" 段），三条原则：

- **React 安全**：从不删除或搬迁 React 拥有的节点——仅通过内联 `style` 隐藏文件夹字形（React 不会重写这些节点的 `style`），在旁插入自带 `data-sshwsp-mark` 的 svg。
- **自愈**：`MutationObserver` 监听 `document.body`，React 重建行节点后自动重新施加替换；工作区不再远程时同样自动还原。
- **身份匹配**：从 live `workspaces` store 的 `getSnapshot()` 取 id / title 集合（服务不可达时退回 `/status` 的 `workspaces` 数组）。侧栏行按工作区 **id** 匹配；选择器菜单行与会话页 hero 工作区按钮只有标题，按 **title** 匹配，hero 在会话刚建立时可能显示路径 basename，故 basename 也计入标题集合。

装饰同时覆盖三处展示：侧栏工作区行、侧栏选择器菜单行、会话页 hero 工作区按钮。

### 按主机操作系统分形

标记**按主机的 `os` 钉值**选形（见 [hosts.md](./hosts.md) 的 `os` 字段），形状表由 React 图标与 DOM 装饰共用一份（`OS_MARK_SHAPES`）：

| os | 图形 | 图形描述 |
| --- | --- | --- |
| `win` | 窗格 | 四块圆角窗格（2×2） |
| `mac` | ⌘ | 命令键环形方（Lucide command 的 16px 缩放） |
| `linux` | `>_` | 终端提示符两笔（16px 下比企鹅剪影清晰） |
| 未钉 | 双箭头 | 原有通用 SSH 标记（45° 相对双 chevron） |

OS 数据的流向：`ssh://alias/…` 路径解析出别名 → `/hosts` 回复里的 `os` 建成别名映射（**只收钉值**：未钉的条目与 `~/.ssh/config` 回退主机保持通用标记）→ 按 id 与 title/basename 两个身份维度落表。拉取时机两处：面板 `refresh()` 的既有 `/hosts` 请求顺带喂给标记层（编辑器保存后立即生效），插件 boot 时独立拉一次（覆盖不开面板的侧栏 / 选择器 / hero）。选形变化时替换整枚 svg 节点（`data-sshwsp-os` 记当前值，钉值改动原位换形），React 组件 `OsMarkIcon` 同表出形——面板「已挂载的工作区」行直接按行路径解析；「添加工作区」锚定菜单的「远程」入口是概念而非主机，保持通用双箭头。

### 主机别名标签（名称下的小标签）

主机编辑器里开启「在工作区名称下显示主机标签」（存储字段 `aliasTag`，**默认关闭**）后，同一套标记通道会再给侧栏工作区行挂一枚**名称下方的标签**：凡是挂载自该主机的远端工作区，行标题的正下方显示一颗小号字体的圆角药丸，内容为该主机的别名。样式跟随主题变量（暗色随宿主 shell），超宽省略号截断、`title` 悬停提示完整别名；行由 CSS 放开固定行高（`data-sshwsp-aliastag-row` → `height: auto; min-height: 34px`）自然长高容纳第二行——绝不裁字、不压相邻行；开关关闭时标签与行高放开一并撤除，零残留。

两个实现要点，都是防回归的：

- **标签文本不是文本节点**。标记层靠 `row.textContent` 做行身份匹配（OS 选形、置灰判定都靠它），标签若带真文本会污染匹配——所以文本存放在 `data-sshwsp-aliastag` 属性里、由 CSS `content: attr()` 渲染，DOM 里始终是空 span。
- **同一身份维度落表**。别名沿 id / title / basename 三种行身份拼写各落一份映射（与 OS 同构），行以 `aliasIds` / `aliasTitles` 找到自己的主机，再查 `/hosts` 回复建起的「开了标签的别名」映射；`/hosts` 拉取时机与 OS 分形相同（面板 `refresh()` + boot 各一次），主机改名或关闭开关后下一次重绘即刷新/撤除。防重插入由标签 span 的 marker 属性天然幂等，行 DOM 被 React 复用给另一工作区时原位改写属性。

该主机的**每一个**工作区行都有标签；浮动远端卡片里显示的正是同一张原生行，因此随通道一并生效，无需单独处理。

### 停用工作区的置灰

已停用（`detach` 过）的工作区，侧栏那一行会被打上 `data-sshwsp-disabled="1"`，
由 CSS 降到 50% 不透明度并在行尾加一枚 `⏻` 标记，**同时把这一行里的按钮变成不可点**：

```css
[data-sshwsp-disabled="1"] button,
[data-sshwsp-disabled="1"] [role="button"] { pointer-events: none; opacity: 0.4; }
```

置灰只是装饰，真正拒绝点击的是这条规则。一个看灰了却仍能触发「新建会话」「重命名」
「删除」的行是在谎报，用户只有点下去、拿到错误之后才会发现。用 CSS 而不是拦 DSH 的
点击处理器，是因为后者属于和宿主抢控制权，宿主一改版就会崩；选择器写成通用的 `button`
而不是本插件自己的类，是因为那些按钮是 DSH 画的。

**工作区标题那一行本身仍然可点击**：展开分组是看清「停用保留了哪些会话」的唯一途径。
所以规则只落在 `button` / `[role="button"]` 上，不落在标题行上。

**它下面的会话行则整行不可点**——这里的情况相反：会话行本身就是「打开会话」那个控件，
只把它的按钮置灰会把唯一要紧的动作留着。这类行按行键单独作用域：

```css
[data-row-key^="session:"][data-sshwsp-disabled="1"] { pointer-events: none; cursor: not-allowed; }
```

`pointer-events` 只挡鼠标，键盘路径由脚本补 `inert` + `tabindex="-1"`（见
[unmount-modes.md](./unmount-modes.md) 的「置灰」一节）。会话行是 `session:<id>`，
**不携带任何工作区信息**，所以成员关系由 `/status` 的 `workspaces[].sessionIds` 下发。

真正的恢复入口是面板里的「启用」按钮。

身份匹配需要 id 与标题两套集合。这里有个容易踩的坑：`readLiveWorkspaces()` 会从
DSH 自己的 store 重新收集身份，而那个 store **不知道**本插件的停用清单，所以停用
路径单独保存在 `knownDisabledPaths` 里并在每次重新收集时传回去——否则置灰会在
下一次 MutationObserver 回调时消失。

## 面板：自动注入内容展示区

「Agent 提示词」区之后是「**自动注入内容**」只读展示区（好设计硬性条款的落地：

1. **工具公告**——`SSH_WORKSPACE_GUIDANCE` 全文（每个会话注入的系统提示词公告）；
2. **local-exec 技能**——模型技能目录里注册的 `local-exec` 技能的 name /

3. **Niubash 使用要点（状态门控）**——每个 win 主机（或有部署记录的主机）一行，

数据来自一条既有风格的路由 `GET /api/dsh-ssh-workspace/injected`；面板打开时拉

## 面板：已挂载与已停用

「远程工作区」面板把工作区分成两段，互斥：

| 分区 | 内容 | 每行操作 |
| --- | --- | --- |
| 已挂载的工作区 | `/status` 的 `mounted[]` | 「卸载」→ 就地展开确认行 |
| 已停用的工作区 | `/status` 的 `disabled[]` | 「启用」 |

**卸载是两步的**：第一次点击只展开确认行（附带「同时删除工作区记录」复选框），
第二次点击「确认卸载」才真正执行。这个动作会影响到该工作区登记的全部会话，一次点击
就执行不合适。

两种模式的后果**只写在「卸载」按钮的悬停提示里**（`mounted.detachHint`，展开确认行后
由「确认卸载」沿用同一个 `title`）：未勾选则工作区记录与会话都保留、左侧那一行仍在
（置灰）、随时可重新启用；勾选则工作区记录被删除、会话归档。不再在确认行里另起一行
常驻文字——那行说明会随复选框变化而要重写一遍，而提示只需要说清两种模式的区别。

两个模式分别对应什么，是这一段的验收口径：

| 复选框 | 模式 | 侧栏那一行 | 面板这一行 | 会话 |
| --- | --- | --- | --- | --- |
| 不勾（默认） | `detach` | **保留**，置灰且按钮不可点 | 移到「已停用」分区，可「启用」 | **保留，不归档** |
| 勾选 | `deregister` | **删除** | **删除** | 归档，不删除 |

「保留记录却不保留会话」是自相矛盾的：`detach` 留住侧栏那个分组，就是为了让用户还能
点开它；把会话归档等于把分组内容清空——行还在，点开却是空的，比删掉更让人困惑。所以
归档跟随「删除记录」这个勾选，而不是独立开关。

勾选时的「两边都删除」是**必须同时成立**的：删掉工作区记录已经让侧栏那一行消失，
而面板的「已停用」分区由持久化的停用标记驱动——如果只删记录、不清标记，面板会继续
为一条在任何地方都不存在的记录提供「启用」按钮，而运行时围栏又拒绝这个已经无法
再启用的路径。所以 `deregister` 会同时清掉**持久清单**与**运行时围栏**两处标记。

「已停用分区始终渲染」只针对 `detach`：这是用户得知「卸载之后还留了个东西可以
启用」以及「它去哪了」的唯一途径——如果只在有内容时才渲染，第一次卸载的用户会
以为工作区被永久删除了。

已停用行的样式是 `opacity: .62` 加一个「已停用」小标签，**不使用
`pointer-events: none`**：这一行存在的意义就是它的「启用」按钮。

## 面板：主机与端口转发

主机区每行一个 alias，右侧是「断开」；端口转发区列出**已存映射**与临时隧道，
顶部有「启动时自动开启隧道」总开关。`os === 'win'` 的主机卡片另有
「初始化 Niubash」按钮（见下）。

### 「初始化 Niubash」弹窗

点击弹出（与主机编辑器同一对话框模式）：

- **当前状态**：打开时一次查询（`GET /niubash/status`），显示「已初始化 /
  未初始化 / 探测到已有部署（未记录）」；已初始化展示远端路径、版本、时间、
  放置方式，以及本进程信任的载荷（包内自带 = 离线可部署 / 内置 pin = 联网下载）。
- **放置路径三选一**：项目工作区（下拉选该主机已挂载的工作区，没有已挂载
  工作区时禁用并提示）/ 用户目录（**默认选中**，也是自动部署勾选框的默认
  目标）/ 自定义目录（绝对路径输入框）。弹窗每次打开都回到「用户目录」这个
  默认推荐项，不记忆上一次的选择——放置方式在这里当场选。
- **开始初始化**发起部署（`POST /niubash/init`，一次请求带回全部结果，不轮询），
  结果展示上传文件数 / 字节 / 远端校验行或错误；进行中按钮变为**取消**
  （abort fetch → 服务端同一 AbortSignal 中止下载 / 上传 / 校验）。
- 已初始化的主机按钮语义不变：弹窗可查看详情，也可**重新初始化**
  （换放置路径或升级版本；强制重建复用既有 force / 原子替换逻辑）。

三级加载路径的完整语义见 [hosts.md](./hosts.md) 的「Niubash 三级加载路径与初始化」。

### 两条「断开」路径必须在面板上不可区分

面板读的只有三个字段：`live`（是否真有 listener）、`enabled`（用户的意图）、
`error`（是否需要解释）。两个入口都指向同一个关闭方法，所以三者逐字段相同：

| 入口 | 走的路径 | `live` | `enabled` | `error` | 面板那一行 |
| --- | --- | --- | --- | --- | --- |
| 主机行的「断开」 | `savedForwards.closeAlias(alias)` → 逐条 `closeById` | `false` | `false` | 无 | 已断开 + 开启，**无红字** |
| 端口行的「断开」 | `closeById(id)` | `false` | `false` | 无 | 同上 |
| 连接意外掉线 | `ForwardManager.closeForAlias()` → `onClosed` | `false` | `true` | `"SSH connection closed"` | 已断开 + 开启 **+ 红字「连接已断开」** |

第三行才是故障：连接断得不是时候，所以要保留意图（下次可一键恢复）并留下原因向用户
解释。前两行是用户主动完成的动作，留下原因等于把成功的操作报成故障，后面还会跟着
「启动时自动开启隧道」的暗示——而用户刚刚明确关掉了它。`forwards.lost`
（「连接已断开」）只在 `error` 里含 `connection` 时渲染，因此主动断开后不会出现。

主机行「断开」的 toast 在拆掉了隧道时报数：`hosts.disconnectOkForwards`
（「已断开连接，同时关闭 {n} 条端口转发」），`n` 来自响应的 `closedForwards`；
没有隧道时用 `hosts.disconnectOk`。

### 面板：持久远端会话

`status.shells` 非空时才出现「持久远端会话」一区，每行 `alias [session]` + 状态
（`存活` / `已结束`）。它是一个**只读**列表——这一区不提供开关或关闭按钮，
因为会话的生命周期归 agent 的 `ssh_workspace_shell` 管（同一 `alias` 可并存多个
命名会话）。空列表**整区不渲染**，避免暗示面板拥有一个它并不拥有的控制项。

## 路径的展示拼写

两处纯展示的替换，把 `ssh://alias/path` 显示为 `ssh://alias@/path`（读起来像 SSH 地址）：

- 工作区悬停卡片（hover card）中的路径；
- DSH `PathLabel` 单元格：文件面板头部、文档预览标题、交付物列表。

只改渲染文本，复制行为与所有功能消费方保持真实拼写。规则细节见 [protocol.md](./protocol.md) 的「显示规则」。

## 文件进任务：拖拽与右键

侧边栏文件树的文件与文件夹（`li[data-files-entry="file"|"directory"]`）有两种手势把路径加入当前会话的任务：

- **左键拖到输入框**：拖动经过输入卡（`[data-composer-card]`）时卡片显示虚线高亮（内联 `outline`，拖拽结束/离开即清除），松开即插入引用 chip；
- **右键 → 菜单**：行上弹出锚定菜单（复用 `.sshwsp-flowmenu` 样式，视口内钳制）。菜单内容取决于该行是否落在远端工作区：

  | 菜单项 | 出现条件 | 说明 |
  | --- | --- | --- |
  | 「添加到任务」 | 总是 | 菜单项副标题直接显示将要插入的 `@` 拼写，点击插入 |
  | 「下载到本机」 | 仅远端行 | 目录行**禁用**并说明「暂不支持下载整个目录」（整棵树请用 `recursive` 上传反向、或远端打包） |
  | 「上传文件到此目录」 | 仅远端行 | 文件行传到它的父目录，目录行传到它自己 |

  本地工作区的行只有「添加到任务」——`GET /download` 与 `POST /upload` 对本地路径没有任何可对话的对象，摆出这两项等于承诺一个该行并不具备的能力。

插入与「`@` 补全里选中候选」走同一条管线：取主会话 composer 的 `captureInsertion()` 跨度，经会话作用域的 `slash/input-insert-reference` 事件交给编辑器——chip 节点、序列化与失效判定因此与补全完全一致（插入后可继续输入、照常提交）。会话监听不声称该事件时降级为纯文本插入；输入框不可用或路径不可表示时给出 toast。

拼写规则与 `@` 补全一致：树根即会话 cwd 时用**工作区相对路径**（`/` 分隔），否则保留绝对拼写；含空格按引号语法（目录保留开引号）。带控制字符或双引号的路径拒绝插入。

实现要点（`lib/client.js` 的 "Composer file bridge" 段）：行的 `draggable` 标记并入 DOM 装饰的同一趟 pass（`MutationObserver` 触发、rAF 合并）；拖拽只写入自定义 MIME、**不写 `text/plain`**，因此不触发输入框的文本粘贴，也不会与 DSH 的「拖入文件」浮层冲突；文档级 capture 监听 `dragover`/`drop` 判定输入卡并转发手势；右键菜单在滚动 / resize / 失焦 / Esc / 点击外部时关闭。手势面向**主会话**的输入框（文件树跟随主会话，二者工作区根一致时用相对拼写）。

## 文件面板与文档预览

「工作区文件」侧边栏与文档预览无需插件改动——它们经 `ctx.fs` 读取，远程工作区下自然由 SFTP 提供（列目录、读文本、写回均同本地工具一致），大文件预览按块流式读取。

插件往这个面板加了**一个**按钮：`sidebar.right.tab.files.actions` 插槽里的「上传文件到此目录」。它读槽位给的 `absolutePath`（面板正在显示的目录），所以上传落在用户眼前那个目录，而不是猜一个根。目录不能作为一个文件下载，因此头部**没有**下载按钮——下载在上面的行菜单里，那里目标明确。

非远端的工作区列表不渲染这个按钮：同一个面板也会显示本地目录，摆出一个只能对远端工作的控件会谎报能力。

已知差异：远端的变更监视**优先走 `inotifywait` 推送**（远端装了该工具时即时上报，不受元数据精度限制）；没有该工具时回退到**轮询式**快照比对——基础约 2 秒一次，空闲目录自适应退避到 5–10 秒、变更后立即回到 2 秒，文件树 / 预览会自动刷新。轮询路径下 SFTP 元数据无亚秒时间戳，同一秒内等长的连续改写可能不触发刷新（增、删、改名总能感知），此时重新打开或重新读取即可看到最新内容。
