# 被扩展说明

> 定位：本插件扩展了 DSH 官方界面哪些「没有插槽的位置」、用什么手法、与其它
> 做同一件事的插件（`dsh-ao-local`、`DSH-better-sidebar`）如何共存、以及哪一
> 方改版时会怎样降级。

DSH 给插件留的插槽覆盖了面板、主视图、会话页与文件面板，但**工作区行右侧的
「更多」菜单没有工作区级的插槽**（`sidebar.workspaces` 只有会话级孔位，菜单项
是 `ProjectRowItem` 组件内硬编码的 `rename` / `delete` 两条）。要在那里加自己的
入口，只能做 DOM 注入。本文件记录这一层扩展的契约。

## 一、被扩展的位置

| 位置 | DSH 的实现 | 我们做什么 |
| --- | --- | --- |
| 侧栏工作区行 ⋯ 菜单 | `ProjectRowItem` → `Menu`（`portal: true`，`div[role="menu"]` 挂在 `body`） | 追加「分隔线 + SSH 远程工作区 ▸」一级项与自绘二级子菜单 |
| 侧栏工作区列表（树体） | `AnimatedRows` 的 `div[role="tree"]`（本身就是滚动容器），其父 `div.treeBody` 已是 `position: relative` | 插入插件自有的绝对定位卡片层；行级只加标记属性（`data-sshwsp-float-hidden`），不删不改 React 节点 |
| 侧栏工作区行 / 会话行 | 行键 `data-row-key="workspace:<id>"` / `"session:<id>"` / `"overflow:<id>"` | 同上：加/摘标记属性，配一条 `display: none !important` |
| 工作区选择器菜单行、会话页 hero 工作区按钮 | 只有标题，没有工作区 id | 按标题隐藏（并要求标题命中本插件 marks 的远端身份集合，避免误伤本地同名工作区） |
| `shell.overlay` 槽 | 官方 list 槽 | 注册浮动远端「添加 / 管理」对话框，使其不依赖侧栏面板 |

**不使用**的扩展方式：不删改 React 拥有的节点、不改核心的 store、不覆盖核心的
点击处理器、不以构建产物类名（`_viewport_abc123` 之类）作为**样式**钩子（只作为
一次性定位查询，与 ao-local 的 `tryInjectOfficialMenu` 同一手法）。

## 二、注入是被追加的，不是被替换的

菜单注入的硬约束：**只追加，且追加在末尾**。

- 其它插件先注入的项（`dsh-ao-local` 的 归档 / 收藏 / 快速搜索 / 复制工作区目录
  地址，`DSH-better-sidebar` 的 独立工作区 / 复制链接 / 新窗口打开 等）保持原位、
  原顺序、原节点；
- 我们的块是菜单内容区的**最后一个子节点**，带 `data-sshwsp-float-item` 标记，
  重复触发不会二次注入（marker 防重）；
- 注入增高菜单后做一次**视口底部夹取**（超出视口 12px 边距就把 `menu.style.top`
  上移），与 ao-local / better-sidebar 的同款处理保持一致；
- 我们的二级子菜单是自绘的嵌套 `div[role="menu"]`（定位在父行右侧、贴边翻转、
  贴底上移、hover 开 + 点击兜底、Esc / 菜单外 pointerdown 收起），挂在父菜单容器
  内，父菜单关闭时天然随迁。

### 与 ao-local / better-sidebar 的具体共存点

| 插件 | 注入内容 | 我们的约定 |
| --- | --- | --- |
| `dsh-ao-local` | 工作区 ⋯ 菜单的归档 / 收藏 / 快速搜索 / 复制目录地址 | 不读、不改、不移除；我们的块始终排在它们之后 |
| `DSH-better-sidebar` | 工作区 ⋯ 菜单的「独立工作区 ▸」与组动作 | 同上；两边各自用不同 marker（`data-dsh-workspace-link-item` / `data-sshwsp-float-item`），互不识别也互不干扰 |
| 任何后来者 | 任意菜单项 | 追加顺序即安装顺序；谁后注入谁更靠后，冲突面为 0 |

两边都不要求对方存在：`dsh-ao-local` / `DSH-better-sidebar` 未安装时本功能照常
工作；反之亦然。我们也不依赖它们注入的任何 DOM 或全局变量。

## 三、降级契约

核心改版时，宁可**少一项**，不可坏页：

| 核心改动 | 结果 |
| --- | --- |
| 工作区「更多」锚按钮的 `aria-label` 模板变了（zh「工作区“{name}”的操作」/ en "Workspace actions for {name}"） | 捕获不命中 → 菜单完全不受影响，只是少了一项；浮动入口不可达 |
| 行键不再是 `data-row-key="workspace:<id>"` | 同上（菜单项仍会出现，但拿不到父工作区 id，点击后不注入） |
| 菜单内容区的 `[class*="_viewport"]` 类名变了 | 退化为追加到 `menu` 本体（仍可见，位置可能略偏） |
| 菜单不再是 `body` 下的 portal | 观察器看不到新增的 `[role="menu"]`，不注入（菜单原样） |
| 树体不再是 `position: relative` | 卡片定位漂移；行隐藏仍生效（属性 + CSS 与定位无关） |

上述任何一条都**不会抛错到页面**：菜单路径只做 DOM 查询与追加，装饰路径在
`requestAnimationFrame` 回调里执行，异常只进 `console.warn`，不影响应用。
`aria` 模板失配时甚至不会走到那段代码。

## 四、卸载与清理

- 菜单注入的 disposer 摘掉文档级 `click` / `keydown` / `pointerdown` 监听、断开
  `MutationObserver`、收起并移除注入块；
- 装饰层的 disposer 移除卡片、摘掉区域属性与所有行标记；
- 对话框的状态与监听、`shell.overlay` 槽的注册都经 `ctx.effect` / `apply` 返回的
  disposer 释放；
- 样式与插件其它界面共用**模块级注入的那一张样式表**（既有做法：`injectStyles()`
  带 `data-plugin-css` 守卫，只注入一次），因此不随卸载单独移除——但卸载会把所有
  由它生效的属性（`data-sshwsp-float-*`）摘干净，样式表本身不会作用于任何节点；
- 因此 HMR 重新物化或插件停用时不会留下第二份监听、第二张卡片或「隐藏了但没有
  任何东西负责恢复」的行。
